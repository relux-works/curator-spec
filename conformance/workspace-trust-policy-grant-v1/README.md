# CIP-0020 policy-grant specification witnesses

This separate, unreleased corpus implements the acceptance examples for
[CIP-0020 §2.1](../../cips/CIP-0020-workspace-trust-ledger.md#21-policy-derived-grants-q1-first-slice).
It does not change the original A1 record, vectors or released conformance
manifest. Passing it proves specification consistency, not runtime support.

- `positive.json` supplies one complete proposed event and independent
  synthetic policy/registration/approval/launch observations. Its policy digest
  is SHA-256 of the complete entry's CCJ-1 bytes. No observation is obtained
  from a live filesystem, authenticated command or vendor process.
  `approval_source` describes the earlier operator/keeper policy command,
  not the current launch caller; valid pre-approval needs no repeated prompt.
- `schema-cases.json` applies one named mutation to the positive event and
  records the expected structural/semantic verdict. Missing required fields,
  impersonated event type and invalid history retain nearby valid controls.
- `vectors.json` contains named positive/negative pairs. Each side starts
  independently from `positive.json` and applies its ordered `changes`.
  Expected verdicts are published data, not regenerated by the oracle.
  A refusal has `admitted: false`, `event: null`, `surfaces: null`; successful
  authorization retains `event: policy-grant`, never `explicit-grant`.

Required pairs cover package self-trust and hook grants, stale entry digest,
revoked consent, changed hook bytes, unknown checkout and a noncanonical
destination spelling. Further pairs cover forged/unapproved issuers, policy
edits, expiry, registration/repository drift, lane/environment scope, direct
host redirection, host-key pins, config-command routing, adapter qualification,
unreadable private state and unlisted native approval with an empty hook list.

Run `python3 tools/workspace_policy_grant.py` or `python3 tools/validate.py`.
Run `python3 -B -m unittest discover -s tools -p 'test_workspace_policy_grant.py' -v`
for the publication entry, invalid-verdict plant, byte/digest controls,
read-only admission and policy edit/removal cleanup witnesses. Logs belong
under `.temp/`. Tests also retain original A1 carrier rejection of this event.

The cleanup witnesses model durable revocation before removing only unchanged
owned keys, retaining conflicts/unreadable homes as pending, other current
support and idempotent retry. They do not exercise crash recovery or real
vendor-file ownership. Final launch refusal, no partial projection or provider
start on error, command authentication, no-follow filesystem observation,
command-free SSH evaluation and vendor hook discovery/reload/revocation must
be qualified through production entrypoints before activation. A synthetic
boolean is not evidence that a runtime can establish the corresponding fact.
