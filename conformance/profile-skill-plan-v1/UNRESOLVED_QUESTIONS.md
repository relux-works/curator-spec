# Profile skill-plan allocation and adoption questions

This list belongs to the [allocation proposal](../../protocol/profile-skill-plan-proposal.md).
It does not change the current protocol or grant implementation authority.

| Decision | Proposal / remaining gate |
| --- | --- |
| Successor allocation | Accept complete `context-lock-v5` with plan v1 and the new proposed `profile_skill_*` diagnostics, or return an explicit alternate allocation. Preserve published schemas 1–2. Schema-4 preservation remains a compatibility recommendation. |
| Selective boundary | Accept profile-reachable ownership, overlapping direct constraints and read-only unrelated drift reporting. Full global reconciliation is excluded. |
| Consumer adoption | After acceptance, publish the implementation's real install coverage and exact supported release/platform evidence. The abstract corpus supplies no runtime proof. |
| Isolation supplier | Qualify a concrete supervisor-issued exclusive domain witness before live Slice A routing. No machine-wide activation is authorized by this proposal. |
| Protected-command companion | `profile-command-admission`: curator-spec specification owner/L1 integration writer, with Curator command-publication owner, allocates the versioned aqua/mise, POSIX/coreutils, builtin/platform inventory, target aliases and fail-closed admitted-base-PATH checks in environments §9.4 and PSR04. Acceptance of the broader command-safety requirement waits for that accepted allocation; publication adoption waits for runtime qualification. This PR does not deliver it. |
| Managed-session CLI companion | `managed-session-skill-cli`: curator-spec, Curator, curator-run and hosted session manager jointly allocate environments §§9.4/10.2 and Slice B fragment/runtime/hosted bindings. Require final-child PATH and reached-artifact evidence for native and hosted launches, wrong/missing binding refusals and no singleton-shim fallback. Acceptance and runtime qualification gate their respective owner outcomes; this PR does not deliver them. |
| Combined owner outcome | Neither the carrier nor an exclusive fixed PATH closes the protected-command + managed-session requirement. The carrier alone supplies neither companion; the native-first allocation below still needs acceptance and real qualification. Adoption/completion without the applicable authoritative qualification records refuses. |
| Readiness and one-shot | Allocate skill-owned enrollment/readiness separately with skill owners. The companion applies the owner-adopted D-PATH ordering to managed one-shot launches; runtime qualification remains separate. |

The [native-first PATH companion](../../protocol/profile-command-path.md)
now specifies receipt/state shapes and verification, PATH admission and
non-refusing no-export/non-current/hosted-without-carrier availability. This
does not qualify delivery or clear the carrier's combined completion gate.
Joint hosted carrier publication and Slice B all-profile/root/lease/GC remain
dependencies, with curator-run and the session host owning hosted delivery.
